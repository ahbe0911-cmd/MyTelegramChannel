# کانال من — پروژه اندروید و سرویس رمز مشترک

این پوشه شامل کد منبع برنامه اندروید (`android/`) و سرویس رمز مشترک (`server/`) است.
برای ساخت APK می‌توانید از GitHub Actions موجود در `.github/workflows/build-apk.yml` استفاده کنید؛ در این حالت Android Studio روی گوشی/رایانه شما لازم نیست. سرویس Cloudflare باید جداگانه راه‌اندازی شود تا رمز مشترک و تغییر سراسری رمز کار کند.

## این نسخه دقیقاً چه می‌کند؟

- در اندروید صفحه ورود با رمز مشترک نشان می‌دهد؛ بدون وارد کردن رمز محتوای کانال را در برنامه باز نمی‌کند.
- بعد از ورود، پیش‌نمایش **کانال عمومی** را از `https://t.me/s/USERNAME` در WebView نمایش می‌دهد؛ ورود به حساب تلگرام یا API ID/Hash لازم نیست.
- مدیر با یک کلید جداگانه، رمز مشترک یا نام عمومی کانال را از داخل اپ عوض می‌کند. تغییر رمز در پایگاه داده مرکزی ثبت می‌شود و نشست‌های قبلی را نامعتبر می‌کند. برنامه فعال تقریباً هر دو دقیقه و هنگام بازگشت به آن نشست را دوباره می‌سنجد.
- رمز واردشده در تلفن یا کلید مدیر در حافظه دائمی ذخیره نمی‌شوند. هنگام بسته‌شدن کامل برنامه ورود دوباره لازم است.
- پنجره WebView امکان رفتن به کانال‌ها و سایت‌های دیگر را از طریق کلیک روی پیوندها نمی‌دهد.

**محدودیت امنیتی مهم:** عمومی بودن کانال یعنی هرکس نشانی عمومی آن را بداند، خارج از برنامه هم می‌تواند پست‌های عمومی را ببیند. این رمز فقط ورود به رابط برنامه را کنترل می‌کند؛ دسترسی به خودِ کانال در تلگرام را محدود نمی‌کند. برای محتوای واقعاً خصوصی، باید کانال خصوصی بماند و کنترل عضویت تلگرام پیاده شود.

**محدودیت نمایش:** این نسخه از پیش‌نمایش وب رسمی تلگرام استفاده می‌کند، نه یک کلاینت کامل. بعضی رسانه‌ها، پست‌های قدیمی یا کانال‌هایی که پیش‌نمایش عمومی محدود دارند ممکن است در WebView به‌طور کامل نمایش داده نشوند. بعضی لینک‌های داخل پست‌ها عمداً باز نمی‌شوند.

## ۱. راه‌اندازی سرویس مرکزی رمز

۱) یک حساب Cloudflare بسازید و Node.js نسخه ۲۰ یا جدیدتر را روی رایانه نصب کنید. سپس در ترمینال:

```bash
cd my-channel-app/server
npm install
npx wrangler login
npx wrangler d1 create my-channel-db
```

۲) دستور ساخت D1 یک `database_id` برمی‌گرداند. آن را جای `PUT_YOUR_D1_DATABASE_ID_HERE` در فایل `server/wrangler.toml` قرار دهید. سپس:

```bash
npx wrangler d1 execute my-channel-db --remote --file=./schema.sql
npx wrangler deploy
```

۳) چهار secret را به‌ترتیب زیر در سرویس ثبت کنید (هر دستور مقدار را به‌صورت محرمانه از شما می‌گیرد):

```bash
npx wrangler secret put INITIAL_PASSWORD
npx wrangler secret put ADMIN_KEY
npx wrangler secret put PASSWORD_PEPPER
npx wrangler secret put SESSION_SECRET
```

- `INITIAL_PASSWORD` رمز اولیه مشترک کاربران است: ۱۲ تا ۱۲۸ نویسه، بدون فاصله ابتدا و انتها. تا اولین اجرای `/login` از آن برای مقداردهی اولیه استفاده می‌شود؛ پس از آن تغییر رمز از داخل اپ انجام می‌شود.
- `ADMIN_KEY` کلید محرمانه خودتان برای تغییر رمز و کانال است: دست‌کم ۲۴ نویسه تصادفی. این کلید را در APK ننویسید و با کاربران به اشتراک نگذارید.
- `PASSWORD_PEPPER` و `SESSION_SECRET` هر کدام رشته تصادفی مستقل و حداقل ۲۴ نویسه باشند؛ فقط در Cloudflare بمانند. تغییر بعدی `PASSWORD_PEPPER` بدون مهاجرت داده، ورود را از کار می‌اندازد؛ تغییر `SESSION_SECRET` نشست‌ها را باطل می‌کند.
- رمز اولیه و کلید مدیر نباید مشابه باشند. **نمونه‌های قراردادی را به‌عنوان رمز واقعی به کار نبرید.**

۴) نشانی خروجی را از `wrangler deploy` یادداشت کنید؛ مثل `https://my-channel-gateway.YOUR-SUBDOMAIN.workers.dev`. برای هر تغییر تنظیمات سرویس، از داشبورد Cloudflare هم می‌توانید استفاده کنید.

۵) برای اجرای تست‌های سرویس روی رایانه:

```bash
npm test
```

طرح سرویس، خطاهای ورود را بر اساس IP برای ۱۵ دقیقه محدود می‌کند. این مانع همه حملات توزیع‌شده نیست. برای استفاده حساس یا پرترافیک، محافظت تکمیلی مانند WAF/Turnstile و نظارت عملیاتی لازم است.

## ۲. تنظیم و ساخت برنامه اندروید

۱) پوشه `my-channel-app/android` را در Android Studio باز کنید. JDK 17 و Android SDK 35 را نصب کنید. فایل‌های Gradle پروژه از Android Gradle Plugin 8.7.3 استفاده می‌کنند؛ Gradle 8.9 مناسب آن است. اگر Android Studio برای **Gradle wrapper** خطا داد، در همان پوشه با Gradle 8.9 نصب‌شده دستور `gradle wrapper --gradle-version 8.9` را اجرا کنید و دوباره پروژه را باز کنید.

۲) روش پیشنهادی GitHub Actions: در مخزن GitHub به **Settings > Secrets and variables > Actions > Variables** بروید و یک Repository variable با نام `API_BASE_URL` بسازید و مقدار آن را آدرس HTTPS واقعی Worker (بدون `/` پایانی) قرار دهید. سپس از زبانه **Actions** گردش‌کار **Build Android APK** را اجرا کنید. خروجی با نام `MyTelegramChannel-APK` در بخش Artifacts همان اجرا قرار می‌گیرد.

اگر `API_BASE_URL` هنوز تنظیم نشده باشد، workflow برای آزمایش فرایند ساخت همچنان APK می‌سازد، اما ورود برنامه تا زمان قرار دادن آدرس واقعی Worker کار نخواهد کرد.

۳) روش Android Studio: می‌توانید پوشه `android` را باز کنید و هنگام ساخت مقدار Gradle property به نام `API_BASE_URL` را تنظیم کنید. خروجی debug معمولاً اینجاست:

`android/app/build/outputs/apk/debug/app-debug.apk`

این فایل APK نسخه تست است. برای توزیع حرفه‌ای، نسخه release را با کلید امضای متعلق به خودتان امضا کنید.

## ۳. تنظیم کانال و رمز از داخل اپ

۱) برنامه را باز کنید؛ رمز مشترک اولیه را وارد کنید تا وارد صفحه کانال شوید. چون هنوز کانال ثبت نشده، پیام «کانال هنوز تنظیم نشده است» می‌بینید.

۲) از «تنظیمات مدیر»، کلید محرمانه `ADMIN_KEY` را وارد کنید. در کادر کانال، **نام عمومی** مثل `MyChannel123` یا لینک عمومی مثل `https://t.me/MyChannel123` را ثبت کنید. لینک دعوت خصوصی `t.me/+...` قابل استفاده نیست.

۳) در همان بخش می‌توانید رمز مشترک جدید را وارد و «تغییر رمز همه کاربران» را انتخاب کنید. رمز تازه را خودتان به کاربران مورد نظر بدهید. پس از تغییر، کاربران با رمز قبلی دیگر امکان ورود جدید ندارند و نشست فعال آنان در بررسی بعدی باطل می‌شود.

۴) بازگشت به صفحه ورود و ورود با رمز جدید، کانال ثبت‌شده را داخل برنامه نشان می‌دهد. برای عوض‌کردن کانال، نیازی به ساخت APK جدید نیست.

## نکات فنی و آزمون

`server/test/gateway.test.mjs` آزمون ورود، مدیریت، چرخش رمز، ابطال نشست، نرخ تلاش ناموفق و اعتبارسنجی لینک عمومی را دارد. تست‌ها با پایگاه داده ساختگی اجرا می‌شوند؛ **به معنی تأیید استقرار واقعی Cloudflare یا ساخت APK نیستند**. پیش از انتشار برای کاربران، نمایش کانال خودتان، عملکرد WebView روی دستگاه واقعی و سرویس آنلاین را آزمایش کنید.
